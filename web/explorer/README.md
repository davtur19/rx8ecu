# RX-8 ECU Firmware Explorer

Interactive **static** explorer (pre-generated HTML + JS + JSON, zero build step,
zero external dependencies) for browsing the `rx8ecu` project data: functions &
symbols, callgraph, calibration tables (with values extracted from the stock
ROM), function/subsystem documentation, and address lookup.

The whole site is **generated by a single script** and published to **GitHub
Pages** by CI (`.github/workflows/pages.yml`).

## Local usage (3 equivalent ways)

The **exact same site** that GitHub Pages publishes is generated locally into
`web/explorer/dist/` — there are **no local/remote differences**. The CI
workflow only re-runs the same `build_site.py` and uploads `dist/`.

From the repo root, or from `web/explorer/`, pick any of these:

| # | Command | What it does |
|---|---|---|
| 1 | `make serve` | **recommended** — builds `dist/` then serves it on http://localhost:8000/ |
| 2 | `python3 web/explorer/build_site.py --serve` | same as #1 via the builder itself (default port 8000) |
| 3 | `python3 web/explorer/build_site.py` + `cd web/explorer/dist && python3 -m http.server 8000` | build, then serve manually |

Use `make serve-port PORT=8080` (or `python3 web/explorer/build_site.py --serve 8080`)
for a non-default port. Stop the server with **Ctrl+C** — both `make serve` and
`--serve` shut down cleanly, leaving no background processes behind.

`make build` regenerates `dist/`, `make clean` removes it, and `make check`
verifies that `dist/` exists and that `data.json` parses as JSON.

```bash
# quick check that everything works:
make clean && make build && make check
```

Or, for quick offline use without a server: open `dist/index.html` directly
from the filesystem — the page tries `fetch("data.json")` and, if that fails,
automatically loads `data.js` (same dataset, placed next to `index.html`).

> Note: with `file://` some browsers block fetch; the `data.js` fallback covers
> that case. For a full experience (fetch, live search, callgraph canvas),
> prefer one of the three served options above.

## Regenerating the site (one command)

```bash
# from the repo root:
python3 web/explorer/build_site.py
```

The script is **stdlib-only** (no pip packages to install), **read-only** over
the project data, and **deterministic** (identical inputs → byte-identical
output; `--serve` never changes the output). It writes the complete site into
`web/explorer/dist/`:

```
web/explorer/dist/
├── index.html   # app page (assembled from src/index.template.html)
├── app.js       # application logic (from src/app.js)
├── style.css    # theme (from src/style.css)
├── data.json    # full dataset (fetched at runtime)
├── data.js      # window.EXPLORER_DATA fallback for file://
├── models/
│   └── <key>.json   # per-model table values (E500, C500, FB00, FC00, B900,
│                    #  E700, 15120, 32000) — lazy-loaded by the model selector
├── .nojekyll    # tells GitHub Pages not to run Jekyll
└── README.md    # auto-generated build summary
```

`dist/` is git-ignored (`web/explorer/.gitignore`): it exists only to be served
and is rebuilt on every push by the Pages workflow.

## Source layout (src/ vs dist/)

```
web/explorer/
├── Makefile                  # local convenience: build / serve / clean / check
├── data/                     # REQUIRED INPUTS (committed, do NOT add to .gitignore)
│   ├── roms_meta.json        #   9 stock ROM models (cal ID, family, cal region, stats)
│   ├── table_addr_map.csv    #   wide per-ROM address map (1210 rows)
│   ├── table_addr_map_long.csv  # long per-ROM address map (1210 × 9 = 10890 rows)
│   └── MAPPING_NOTES.md      #   methodology (EN translation of the original IT notes)
├── src/
│   ├── index.template.html   # HTML with __GENERATOR__ / __BUILD_STATS__ placeholders
│   ├── app.js                # all application logic (English UI)
│   └── style.css             # dark theme, zero deps
├── build_site.py             # THE builder: dataset + site assembly (+ optional --serve)
├── dist/                     # generated output (git-ignored)
├── .gitignore                # ignores dist/ only
└── README.md
```

`src/` holds the sources; `dist/` is the **generated** static site (copied /
assembled from `src/` + project data by `build_site.py`) and is exactly what
GitHub Pages serves. Edit the sources under `src/` (and `build_site.py`),
never the files in `dist/`.

## What the script reads (read-only)

- `../../symbols/callgraph.csv` — 6953 callgraph edges
- `../../symbols/cal_tables.csv` — 1210 calibration-table entries
- `../../symbols/symbols_60E0FC00.csv` and `..._ghidra.csv` — 60E0FC00 ROM symbols
- `../../symbols/symbols_60E1D400_ida.csv` and `..._merged.csv` — baseline 60E1D400 symbols
- `../../roms/stock/60E1D400.bin` — **real values** of the calibration tables (default model)
- `../../roms/stock/*.bin` — **real values** for the other 8 firmware models
- `data/roms_meta.json` — the 9 ROM models (input; committed)
- `data/table_addr_map_long.csv` — per-ROM table addresses/method/confidence (input; committed)
- `../../docs/functions/*.md` — **content** (title + address + markdown body),
  matched to symbols by exact name, normalized name (no `_hex` suffix) or
  address extracted from the header
- `../../docs/subsystems/*.md` — **content** for the "Documentation → Subsystems" view

## What the site contains

| Section | Content |
|---|---|
| **Dashboard** | counts, category distribution, top functions by degree (hubs) |
| **Functions & Symbols** | live search on name/address, category/ROM/doc filters; click a function → details + callers/callees + **Documentation** section with the real `.md` content |
| **Callgraph** | canvas *ego-graph*: pick a function, depth 1–2, `bsr`/`ref` edge filters; hand-rolled force layout (repulsion + springs + level gravity), pan/zoom, node dragging, click to re-center |
| **Calibration Tables** | browser of the 1210 CSV entries (548 tables + 662 X/Y axes) with filters; per entry: model address, baseline address, mapping method/confidence, type and values; for tables with a map descriptor: **2D heatmap** or **1D chart** with values extracted from the selected model's ROM; otherwise metadata, estimated f32 scalar and raw bytes |
| **Documentation** | index of all `docs/functions/*.md` (including unmatched ones) and `docs/subsystems/*.md`, full-text search and a minimal markdown renderer |
| **Address Lookup** | enter a hex address → containing function, exact table or nearest entries; for tables it also resolves addresses of the currently selected model and shows the baseline + model address side by side |

## Firmware model selector

The header shows a **Firmware model** dropdown with the 9 stock ROMs
(`60E1D400`, `60E0E500`, `60E1C500`, `60E0FB00`, `60E0FC00`, `60E1B900`,
`60E0E700`, `60E15120`, `60E32000`). Switching the model:

- **Table addresses** are taken from `data/table_addr_map_long.csv`
  (per-ROM rows, per-table mapping method + confidence). **No global shift is
  ever applied**: the cal layout drift is piecewise-constant, so every address
  comes from the map.
- **Values** are extracted from the matching `roms/stock/<file>.bin` with the
  same Map1D/Map2D descriptor logic used for the baseline. Tables without a
  descriptor keep the current fallback (raw bytes + estimated f32 scalar).
- Each table row/detail shows a **confidence badge** (`high`/`medium`/`low`,
  from the mapping) and the mapping method. Tables that are not mappable in the
  selected ROM (e.g. the 16 trailing tables of the structurally-different
  `60E32000`) are shown as **not mapped in this model** — no address, no
  values, graceful degradation.
- **Functions/symbols are never adjusted**: the symbol CSVs only exist in the
  `60E1D400` and `60E0FC00` contexts. When the selected model is outside these
  two contexts a note is shown ("Symbols / functions are not adjusted").

### Lazy-loading of per-model values

To keep `data.json` small (~2.3 MB), only the baseline `60E1D400` values are
embedded. The other 8 models ship as `dist/models/<key>.json` (≈0.1–0.22 MB
each), **fetched on demand** the first time the model is selected and then
cached in memory. This works identically on GitHub Pages and on any local HTTP
server (`make serve`). On a plain `file://` open the fetch of model files is
blocked by the browser, so the selector still works for **addresses** (the map
is inside `data.json`), while **values** for non-baseline models show a clear
"values unavailable" note.

## Deep links

The explorer exposes anchor URLs:

- `#sym-0xADDR` — open the Functions & Symbols tab on that function,
- `#tbl-0xADDR` — open the Calibration Tables tab on that table/axis,
- `#doc-<filename>` — open the Documentation tab on that document.

## Notes on the data (ROM contexts)

The project uses **two address contexts** for symbols/callgraph:

- **Symbols + callgraph** → ROM **60E0FC00** (all 3363 callgraph addresses
  resolve into FC00 symbols; 962 nodes have non-FUN names, 911 of them hand)
  and **60E1D400** (baseline IDA names).
- **Calibration tables** → `cal_tables.csv` is labeled `[REDACTED]` (private dump,
  not distributed), but its addresses match **1:1 the verified map descriptors**
  in `roms/stock/60E1D400.bin` (RE baseline), from which the default values are
  extracted. Verification: all 499 descriptors of `60E1D400.bin` find the
  RX8Defs name by pointer.

Extracted values are *physical* values (for integer types: `raw × scale +
offset`, per the Map1D/Map2D descriptor in `c/2DLookup.c` and `c/3dLookup.c`).
Axes are monotonic `f32` arrays.

The cross-ROM table mapping methodology is documented in
[`data/MAPPING_NOTES.md`](data/MAPPING_NOTES.md) (English). The mapping is
**content-identity + per-table drift curve**, not a global shift; confidence is
highest for byte-identical tables (`content_match`) and lower for retuned ones
(`family_shift`).

## GitHub Pages deployment

`.github/workflows/pages.yml` builds the site on every push touching
`web/explorer/**`, `symbols/**`, `docs/functions/**`, `docs/subsystems/**` or
`roms/**` (branches `main` / `master`), then deploys `web/explorer/dist` with
the modern Pages flow (`actions/upload-pages-artifact` +
`actions/deploy-pages`, environment `github-pages`). The site is then served at
`https://<owner>.github.io/rx8ecu/` (or the configured Pages domain).
`data/roms_meta.json`, `table_addr_map*.csv` and `MAPPING_NOTES.md` are
committed inputs under `web/explorer/data/`, so the Pages build has everything
it needs.

## Known limitations

- Per-model values are lazily loaded via `fetch`, so on `file://` (no HTTP
  server) the baseline model is fully interactive but the other models only
  show addresses (values are unavailable and clearly labeled as such).
- The cross-ROM mapping is **content-identity + drift curve**, not a
  disassembly of the target's Map1D/Map2D descriptors: for retuned tables the
  confidence stays `medium`/`low` and the address can be off by a few bytes in
  layout-transition zones. `60E32000` is the worst case (16 unmapped tables,
  mostly `low` confidence) — see `data/MAPPING_NOTES.md`.
- Table values for the baseline are extracted from `60E1D400.bin`: tables
  without a map descriptor in that ROM stay without descriptor values (raw
  bytes + optional estimated f32 scalar).
- The ego-graph is capped at ~320 nodes (with depth 2 + `ref` edges the graphs
  explode); beyond the cap the levels closest to the root are kept.
- The category assignment of functions/tables is a name-keyword heuristic
  (keyword → subsystem): not guaranteed 100% and can be refined.
- The markdown renderer is **minimal** (hand-rolled, zero deps): headings,
  lists, `code`/fenced blocks, **bold**, *italic*, `|` tables, `>` quotes and
  links; no advanced features (images, footnotes, task lists, syntax
  highlighting).
- Some `.md` files are not matched to a symbol (6): case-duplicates
  (`udserrorresponse` vs `udsErrorResponse`), consolidated multi-function docs
  (`dtc_management`), addresses without a symbol (`security_access_handler`) or
  conflicting doc addresses (`mod32_signed`/`div32_signed`). They are all
  visible in the **Documentation** view anyway.

## Suggested next step

For `60E32000` (the structurally distinct build), extract the Map1D/Map2D
descriptors from the ROM itself (scan for pointers to the tables) to raise the
mapping confidence from `low` to `medium`/`high`; cross-validate against the
baseline descriptors so the UI can also report the *element size* (u8/u16/f32)
per table. A further step could be a side-by-side value-diff view between two
selected models.
