# romdiff — cross-ROM diff analysis

Generated by `run_romdiff.py`. It does not modify repo files. Its inputs are read-only.

## Regenerate

```bash
cd rx8ecu
python3 analysis/romdiff/run_romdiff.py
```

Python 3.8 or newer is required. No third-party packages are needed.

## Inputs (read-only)

- `roms/stock/*.bin` — 9 stock 512 KB SH-2E ROMs
- `symbols/cal_tables.csv` — 1210 calibration-table addresses (60E1D400 layout)

## Outputs

| file | contents |
|---|---|
| `REPORT.md` | methodology, matrices, clusters, region analysis, insights |
| `diff_matrix.csv` | all-pairs raw byte diff (file1, file2, byte_totali, byte_diversi, percentuale) |
| `diff_matrix_blocks.csv` | all-pairs shift-tolerant 16B-block content similarity (whole / code / cal) |
| `diff_ranges.csv` | merged ranges that differ per pair, classified by header/code/padding/cal_data/cal_table/tail |
| `cal_table_diffs_baseline.csv` | u16 deltas for each known table vs baseline 60E1D400 |
| `clusters.txt` | clusters based on raw distance and on content distance |

## Two metrics

- **Raw %diff**: the bytes that differ at identical offsets. The value is high
  for every distinct build because the code and table blocks are relocated.
  This is layout divergence.
- **Content similarity**: the percentage of A's 16B windows that exist at any
  position in B. The metric is relocation-tolerant. Use this to group variants.

## Classification bands (anchored to baseline 60E1D400)

See REPORT.md. The tool matches known tables exactly with the 60E1D400 address
map from `cal_tables.csv`. The Z-line build (cal_lo 0x6D300) and the N3M5E build
(~0x715C0) relocate their table block. Therefore the `cal_table` hits are exact
only for the J-line-layout ROMs.
