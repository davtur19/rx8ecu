## INTER-DOC INCONSISTENCIES

### 1. RTOS queue address discrepancy (MINOR)
- IDA_ANALYSIS.md line 58: "100 entries × 8 bytes at 0xFFFFD4E0"
- RTOS_SUBSYSTEM.md line 30: "0x00000400 Queue head ptr · 0x0404 tail ptr · 0x0414 queue entry base"
- **Resolution**: Both correct. 0x400/0x404 are ROM locations containing pointers to 0xFFFFDFB4/0xFFFFDFB6. 0xFFFFD4E0 is the actual RAM queue. RTOS_SUBSYSTEM.md is confusing.

### 2. Task table address ambiguity (MINOR)
- IDA_ANALYSIS.md line 299: "Task table (ROM at 0x6873C)"
- RTOS_SUBSYSTEM.md line 14: "Task table @0xDB14"
- **Resolution**: Both correct but different tables. 0xDB14 = task pointer table (pointers to task entry arrays). 0x6873C = task table (8-byte entries with marker/args/func_ptr). Not contradictory, just different levels of dispatch.

### 3. EEPROM size discrepancy (MINOR)
- KNOWLEDGE.md line 66: "ABLIC S-93C56C, 256 B"
- IDA_ANALYSIS.md line 689: "Estimated size: 2KB (2048 bytes) minimum"
- **Resolution**: The physical EEPROM chip is 256 bytes (S-93C56C). The staging buffer in RAM is 256 bytes. The IDA_ANALYSIS.md estimate of 2-4KB is WRONG — it confuses staging buffer size with EEPROM size. The chip is 256 bytes.

### 4. SecurityAccess subfunction convention (RESOLVED)
- CAN_PROTOCOL.md line 244: "SecurityAccess flow (0x584A0)"
- UDS_SECURITY_MAPPING.md line 18: "r4 = msg_len (16-bit, NOT a pointer), r5 = subfunction byte"
- **Resolution**: Consistent. Both correctly describe the same function.
