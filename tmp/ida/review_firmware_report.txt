5. FPU / FLOATING-POINT HANDLING
================================================================================

PASS (with note) — Float operations in firmware/ are ROM-matching.

  firmware/c/engine.c uses native float operations (direct RAM reads via
  volatile float pointers, arithmetic, comparisons). This matches the
  ROM behavior: the SH-2E has a hardware FPU, and the original ROM uses
  FPU instructions for engine control calculations (dwell, fuel pulse
  width, idle PID, etc.).

  The soft-float pipeline (div_4740 -> ldexp_481C) is used ONLY by
  checkFloatValidity (0x46CC) for square-root validation — a specific
  ROM function, not general float math.

  Key float functions verified:
    c/checkFloatValidity.c  — sqrt pipeline, verified 100k+ inputs
    c/div_4740.c            — restoring sqrt, verified 300k+ inputs
    c/ldexp_481C.c          — float rebuild, verified 300k+ inputs
    c/bitfield_extract_merge.c — frexp, verified 200k+ inputs

  Note: engine.c float ops (e.g., calcDwellTime at line 398-416) read
  volatile float pointers from RAM and perform native float division.
  This is correct for the SH-2E FPU but would need soft-float on a
  pure-integer target. No documentation issue — the platform.h header
  correctly defines the target as SH-2E with FPU.

  0x01B088 in c/FUN_0001b088_1b088.c) — these are correct ROM offsets,
  not hardware register addresses.
